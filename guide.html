Proxmox VE + Talos Linux Kubernetes, fully declarative. Terraform provisions the VMs & LXCs through the Proxmox API, Talos bootstraps Kubernetes, and Argo CD runs everything in this repo as GitOps. Single node, 1 control plane + 1 worker.

Overview

This homelab is driven entirely from version-controlled config on your workstation. Nothing is clicked together by hand: the Proxmox API creates the guests, Talos (an immutable, API-managed Linux) builds the cluster, and Argo CD continuously syncs the manifests in kubernetes/.

Network & VLANs

Three VLANs on the UDM Pro (trunked to the Proxmox uplink on a VLAN-aware vmbr0). VLAN 25 is intentionally dark — no WAN access.

VLANRoleSubnetInternet
20Management10.10.20.0/24yes
24DMZ10.10.24.0/24yes
25Cluster10.10.25.0/24dark
VLAN 25 nodes never touch the internet. They pull container images through the Zot mirror at 10.10.20.101:5000 on VLAN 20. Talos has no SSH and no package manager, so the attack surface is smaller than the old script setup.

Firewall automation

ansible/udm-firewall.yml logs into the UDM with a local admin account, discovers the existing Zone-Based Firewall policies, then applies the rules the cluster needs. VLANs themselves are created in the UniFi UI; Ansible only manages policies.

Backup chain

pod PVC (Longhorn on beta SSD) │ RecurringJob every 6h, retain 8 ▼ in-cluster MinIO s3://longhorn-backups (on alpha → later gamma) │ mc mirror / bucket replication (planned) ▼ friend's MinIO (off-site)
Result: a daily-ish, versioned, off-site copy of every Longhorn volume at your friend's place. The off-site replication leg is wired in once your friend's MinIO exists.

Bootstrap Flow

One command from your PC: cd infrastructure && make all. It runs these phases in order. You can also run each target on its own.

1
make firewall — Ansible configures UDM Pro firewall policies so the VLANs can talk as needed.
2
make infra — Terraform (bpg/proxmox) creates the LXCs and Talos VMs and autostarts them in boot order (registry first).
3
make cluster — Terraform (siderolabs/talos) applies machine configs, bootstraps etcd, and writes kubeconfig + talosconfig.
4
make gitops — Installs Argo CD and applies the root app-of-apps. Argo then deploys Longhorn, MinIO, and your pods automatically.
5
make secrets — Applies the git-ignored Kubernetes secrets (MinIO root, Longhorn backup creds, PostgreSQL).
First-time prerequisites
  • Copy each terraform.tfvars.example → terraform.tfvars and fill in real values (these are git-ignored).
  • Copy ansible/group_vars/all.example.yml → all.yml with the UDM admin login.
  • Run make secrets only after copying each *-secret.example.yaml → *-secret.yaml and editing it.
  • Tools installed on your PC: terraform, talosctl, kubectl, helm, ansible.
Managing the cluster afterwards

Talos has no SSH. Use talosctl --talosconfig … for node-level operations and kubectl --kubeconfig … for workloads. Node changes are config patches in the talos Terraform module, not shell commands.

FAQ

Did we switch from k3s to k8s? Why?

Yes. Talos Linux ships upstream Kubernetes (k8s), not k3s. Talos is immutable and fully API-managed — no SSH, no apt, no drift — which is exactly the declarative goal. For you: kubectl works the same; node config lives in the talos Terraform module as machine-config patches instead of shell scripts.

Is VLAN 25 still dark / no less secure than before?

Still dark by design. Nodes pull images via the Zot mirror on VLAN 20; Talos has no shell or SSH. Security is equal or better than the old script-based setup.

Is there still an "update server"?

No. The old apt-cacher / update-server / load-balancer / admin LXCs are gone. The Zot pull-through mirror (LXC 20101) replaces them for image caching; Talos handles OS updates declaratively.

Can I grow the Longhorn disk later?

Yes — it's just worker_data_disks[0].size_gb in the tfvars. Before provisioning it's free to change; after, a terraform apply grows the disk (shrinking isn't supported). It's currently set to 400 GB to avoid the hassle.

Do I need a self-hosted Git LXC?

Not required — Argo currently syncs from the public GitHub repo. If you want self-hosting, the lightest fit is Forgejo (or Gitea): a single Go binary, ~100 MB RAM, SQLite backend, happy in a small Debian LXC. Add it to lxc.tf and point Argo's repoURL at it (with a read-only credential as a Sealed Secret).

Where do Talos secrets live?

In Terraform state for the talos module (the generated PKI/secrets bundle). Keep that state out of Git and treat it as sensitive. Kubernetes app secrets stay out of Git too — committed only as *.example.yaml templates, applied via make secrets or sealed.
