Homelab Guide

A fully declarative single-node homelab. Terraform provisions the VMs & LXCs through the Proxmox API, Talos Linux bootstraps Kubernetes, and Argo CD runs everything in this repo as GitOps — one control plane, one worker, zero manual clicking.

node pve Talos v1.13.4 Kubernetes v1.34 provider bpg/proxmox GitOps Argo CD storage Longhorn · MinIO

Everything is driven from version-controlled config on your workstation. The Proxmox API creates the guests, Talos builds the cluster, and Argo CD keeps the manifests in kubernetes/ continuously in sync — no hand-clicking, no drift.

Network & VLANs

Three VLANs on the UDM Pro, trunked to the Proxmox uplink on a VLAN-aware vmbr0. VLAN 25 has no internet access by design.

VLANRoleSubnetInternet
20Management10.10.20.0/24yes
24DMZ10.10.24.0/24yes
25Cluster10.10.25.0/24no
VLAN 25 nodes never touch the internet. They pull container images through the Zot mirror at 10.10.20.101:5000 on VLAN 20. Talos has no SSH and no package manager, so the attack surface is smaller than the old script setup.

Firewall automation

ansible/udm-firewall.yml logs into the UDM with a local admin account, discovers the existing firewall policies, then applies the rules the cluster needs. VLANs themselves are created in the UniFi UI; Ansible only manages policies.

Guest Inventory

Names follow a <vlan><ip> scheme, so the name tells you where it lives: 24010 = VLAN 24, host .10; 25101 = VLAN 25, host .101. The Proxmox vmid matches the name.

Kubernetes storage classes

💾

Longhorn

Default class, LUKS-encrypted. Replicated block storage (1 replica on the single worker) on the beta SSD. Every pod PVC lands here — and because volumes are encrypted, every backup is ciphertext.

🪣

MinIO

In-cluster S3 on alpha for now. Holds the longhorn-backups bucket; later moves to the gamma drives.

📁

local-path

Non-default. Backs MinIO's own volume from /var/mnt/alpha on the worker.

Backup chain

🌍 Friend's MinIO
off-site copy · ciphertext only
Volumes are encrypted with your longhorn-crypto passphrase before they reach MinIO, so your friend hosts the data but can't read it. The off-site leg activates once his MinIO exists. Full rebuild & DR-test steps live in docs/disaster-recovery.md.
Escrow your longhorn-crypto passphrase off-site (password manager + offline). Lose it and every backup — including yours — is permanently unreadable.

Bootstrap Flow

One command from your PC: cd infrastructure && make all. It runs these phases in order — or run any target on its own.

1
Firewall make firewall

Ansible configures UDM Pro firewall policies so the VLANs can talk as needed.

2
Infrastructure make infra

Terraform creates the LXCs and Talos VMs and autostarts them in boot order (registry first).

3
Cluster make cluster

Terraform applies Talos machine configs, bootstraps etcd, and writes kubeconfig + talosconfig.

4
GitOps make gitops

Installs Argo CD and applies the root app-of-apps. Argo then deploys Longhorn, MinIO and your pods automatically.

5
Secrets make secrets

Applies the git-ignored Kubernetes secrets (MinIO root, Longhorn backup creds, PostgreSQL).

Getting Started

Everything you personally must create or fill in before cd infrastructure && make all will work end-to-end. Run it all from your PC.

1 · Things you create outside the repo

🔑

Proxmox API token

In Proxmox: Datacenter → Permissions → API Tokens. Create a token (e.g. root@pam!homelab), give it privileges on /. Paste the USER@REALM!ID=UUID into pve_api_token.

🌐

UDM Pro local admin

UniFi → Settings → Admins → add a local admin (not the Ubiquiti cloud account). The firewall playbook logs in with it. Put it in group_vars/all.yml.

🧱

Proxmox host prep

Make vmbr0 VLAN-aware; trunk VLANs 20/24/25 on the UDM uplink port. Have the LXC template and storage pools (beta, alpha) present.

🔐

SSH key

Your public key goes in ssh_public_keys — injected into the LXCs and the gameserver VM (Talos nodes have no SSH).

📡

VLANs on the UDM

Create networks for VLAN 20 / 24 / 25 in UniFi (already done in your case). Ansible only manages firewall policies, not the networks themselves.

🧰

Tools on your PC

terraform, talosctl, kubectl, helm, ansible — plus reachability to ports 8006 / 50000 / 6443.

3 · Tuning without rewriting the repo

Almost everything is data in *.tfvars / YAML. Common changes:

Different network layout / VLANs

Edit the vlans map (id → gateway) in terraform/proxmox/variables.tf and the matching vlan_tag / vlan_id locals in images.tf. Move a guest to another VLAN by changing its vlan_key + IP in the tfvars. Set enable_vlan_tagging = false to deploy everything untagged during a transition. Update the firewall rules in ansible/vars/firewall-rules.yml to match.

Resize / re-spec a node

Change cores / memory / disk_gb for any entry in controlplanes, workers, lxcs or gameservers and re-apply. Disks grow on apply (shrinking isn't supported). Worker data disks live in worker_data_disks (e.g. the 400 GB Longhorn disk).

Add or rename nodes / guests

Guests are for_each maps keyed by the <vlan><ip> name. Add an entry to grow the fleet (e.g. a second worker, another LXC). Keep the controlplane_nodes / worker_nodes maps in the talos module in sync with the names/IPs in the proxmox module.

Change storage pools

Set vm_storage / ct_storage / image_storage in the tfvars, and the storage field of each worker_data_disks entry. When the 6×18 TB gamma drives arrive, attach them to the worker and point MinIO at them — pods only see the S3 endpoint, so no app changes.

Add another gameserver, or skip it

Add entries to the gameservers map (each becomes a Debian + Docker + Wings VM). Set it to {} to provision none. Pelican Panel in kubernetes/apps/pelican-panel manages whatever Wings hosts you register.

4 · Good to know

What runs the cluster?

Talos Linux (immutable, API-managed — no SSH, no apt) running upstream Kubernetes. Operate nodes with talosctl and workloads with kubectl; node changes are machine-config patches in the talos Terraform module.

How do I add a new service / pod?

Create kubernetes/apps/<name>/ with your manifests, commit, and Argo CD deploys it (the app-of-apps recurses and ignores *.example.yaml). Use Longhorn for volumes and the in-cluster PostgreSQL / MinIO for data. See docs/roadmap.md.

Where do secrets live?

No real secrets in Git — only *.example.yaml templates, applied via make secrets or sealed with kubeseal. Talos PKI lives in the talos Terraform state; keep that out of Git and treat it as sensitive.
